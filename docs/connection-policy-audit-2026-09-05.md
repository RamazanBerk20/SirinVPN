# Typography and independent connection policy — 5 September 2026

This pass separates traffic protection from connection recovery and fixes the typography without changing the application's layout direction, custom title bar, thin outer border, or background/tray lifecycle. It supersedes the bundled protection description in the [previous refinement report](refinement-audit-2026-09-05.md). The changes remain in the working tree for review.

The native font inspection found that Manrope was loading correctly, including its variable weights and Latin extended characters. The main problem was component styling: metric values and textual states inherited large JetBrains Mono styling, with further overrides in device/server metric grids. This was an application-level inconsistency, not evidence of broken KDE fonts.

Ordinary interface text now uses locally bundled Inter Variable. Shared typography roles set page titles to 28px/600, section headings to 16px/600, body text to 15px/400, and secondary text to 14px/400. Measurements use 25px/600 with tabular, lining numerals; textual states use 15px/500. IP addresses, fingerprints, and exact identifiers retain JetBrains Mono. English and Turkish glyph coverage and 400/500/600 face loading were checked against the actual local assets. Both font licenses ship with the app. No remote font loading, global zoom, desktop scaling changes, or Linux font-smoothing workaround was added. Tabular numerals keep changing digits aligned within the UI font. [Inter documentation](https://rsms.me/inter/), [MDN numeric typography](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-variant-numeric).

Native WebKitGTK checks passed on private KWin outputs at 100% and 125% scaling, including unavailable states, numeric metrics, long Turkish names, form controls, and all four connection controls. The fractional test changes only its disposable virtual output. Native captures and browser fixtures demonstrate rendering; they are not measurements from a connected VPS. Loading and unavailable states remain truthful.

| Control | Configuration and behavior |
| --- | --- |
| Kill switch | An independent helper policy controls the traffic block. Its effective state comes from privileged inspection, not the saved checkbox. |
| Automatic reconnect | Independently permits recovery attempts after an established connection fails or the initial bounded connection plan is exhausted. Disabling it does not remove protection. |
| Choose transport automatically | Builds one bounded plan of supported transports, including pinned TLS when available. Manual selection and automatic selection leave the other policy flags unchanged. |
| Connect on system startup | Separately controls boot activation of the last acknowledged connection. Launching the GUI remains an app preference. This is not an always-block-after-Disconnect mode. |

On an unexpected failure, kill switch on/reconnect on retains the block while retrying; on/off retains it while awaiting manual action; off/on retries without a kill-switch claim; off/off stops recovery without a kill-switch claim. A manual **Resume** uses the acknowledged active policy and keeps its block in place, even if different preferences are waiting for the next connection.

**Manual Disconnect preserves the previous policy:** it stops recovery, releases the owned traffic block, and cancels boot connection intent until the user connects again. Saved preferences remain available for the next connection. The disconnect interaction explains the release consequence. Closing the GUI, closing to tray, or quitting the GUI does not invoke Disconnect. No post-Disconnect lockdown control or unqualified reboot-protection promise was added.

Preferences are private, bounded, atomic files scoped to each locally saved server. Schema 2 stores independent `policy.kill_switch`, `policy.automatic_reconnect`, and `policy.connect_on_startup` fields alongside transport, network conditions, and routing. Editing or saving preferences does not change an active device policy; the UI shows pending differences. A new connection is the acknowledged application boundary. The helper rejects a competing server or incompatible active policy instead of silently replacing protection.

Migration reads the old schema without overwriting it until a successful explicit save. The old enabled bundle becomes three enabled flags, preserving its actual firewall, recovery, and boot behavior. The old disabled bundle becomes three disabled flags. Missing preference files retain conservative disabled policy defaults in this release; new on/on defaults are deferred until full release qualification. Invalid, incomplete, or future-version documents fail closed and are preserved. The application does not silently introduce a traffic block during migration.

The backend separation spans Tauri commands, CLI commands, helper protocol 11/request schema 7, root-owned desired configuration schema 2, runtime schema 3, and systemd units. The monitor can run without boot activation or an early firewall service. Old helper requests and old desired configurations remain readable. Key-rotation journals now retain the independent policy and routing; rotation pauses the tunnel without dropping its guard. Both the desktop and CLI use this path. The CLI exposes `--kill-switch`, `--automatic-reconnect`, `--connect-on-startup`, and `resume`; legacy `--persistent` is an explicit all-three shortcut.

Effective status distinguishes off, armed, blocking, failed, and unknown. A successful privileged inspection must match the owned rules before the UI claims enforcement. Observations expire after 15 seconds using boot-relative monotonic time. Stale observations, unreadable rules, and unavailable monitoring do not become “Off” or “Protected.” An absent guard is accepted only after a successful table listing. Legacy sessions without verifiable enforcement remain unknown.

The guard covers IPv4 and IPv6, including DNS. Full-tunnel mode permits the tunnel and narrowly scoped reconnect/bootstrap traffic. LAN bypass is explicit; selected-route mode protects the selected ranges and system DNS while other destinations use the normal network. Unknown IPv6 enforcement stays unknown when the independent verified guard is not active. The application still uses IPv4 tunnel/DNS addresses in this release; blocking IPv6 escape is not equivalent to providing an IPv6 tunnel.

The packet test exposed a real transition issue: deleting and recreating an nftables base chain could briefly unregister its hook, even within a replacement transaction. The implementation now keeps the base chain registered and atomically replaces only the owned chain's rules. Failed transactions retain the preceding rules, retries and transport changes retain the guard, and unrelated firewall tables are untouched. Only explicit release removes the guard. The [isolated test instructions](../tests/network/README.md) document the container, capabilities, and network boundary.

Android retains its real operating-system protection behavior. Its native command rejects unsupported independent combinations rather than simulating Linux firewall controls. Saving supported Android preferences does not activate the VPN. Existing Android feature boundaries and notification privacy controls are preserved. The Pixel 10 emulator verified preference persistence through WebView reload and process restart, rejected kill switch on/reconnect off, and retained a disconnected VPN. Temporary test identities were deleted; app preferences and notification permission were restored.
