## Scope and evidence boundaries

Baseline commit: `9a6b14b15366b67f44b6c85d94072dcb2c847bdc`. The starting tree was
clean. Inventory covered the first-party Rust workspace, React/Tauri interface,
Android plugins, CLI, installer, helper, server, release tooling, packaging,
tests, and documentation. Generated output and third-party dependency source
were excluded from the maintainability inventory.

Automated checks covered source size, compiler/lint errors, known dependency
advisories, secret patterns, privacy invariants, existing tests, and targeted
regressions. Manual review concentrated on SSH/artifact trust, management TLS and
authorization, secret ownership, filesystem/subprocess boundaries, transactional
recovery, platform IPC/capabilities, frontend state, manifests, and operational
scripts. This was a boundary-focused review, not a claim that every line received
independent manual scrutiny or formal verification.

Third-party native code embedded in AARs, AppImage runtime/build helpers, the
Android system image/SDK/NDK, and host OS packages were not comprehensively audited. Dependency results are
time-limited advisory matches, not proof of absence of exploitable defects.

## Changes and confirmed findings

Severity below describes the affected boundary and required attacker access;
dependency severity does not establish exploitability in this application.

| ID | Severity / kind | Finding and correction | Evidence |
| --- | --- | --- | --- |
| F01 | Medium, trust boundary | The management client inherited built-in certificate roots and redirect behavior. It now trusts only the enrolled certificate and disables redirects, referers, proxies, and implicit retries. | Real loopback TLS test accepts the enrolled pin, rejects another certificate, and rejects redirect traversal; privacy gate enforces the client options. |
| F02 | Medium, resource exhaustion | Management JSON replies were read without an application-level size cap. Declared lengths and streamed chunks now have a 1 MiB bound before deserialization. | Tests reject oversized replies both with and without `Content-Length`, and preserve valid/version-rejected envelopes. |
| F03 | Medium, resource/privacy boundary | SSH output and local artifact reads could allocate before checking their limits; debug errors could include remote stderr. Reads are bounded first, sensitive buffers are zeroizing, and remote stderr is withheld in all build modes. | Unlimited-reader and boundary tests; installer tests and disposable provisioning/rollback gate. |
| F04 | Medium, availability | Private management accepted stalled TLS work without explicit concurrency/deadline limits. It now limits sockets to 512, handshake and HTTP/1 header waits to ten seconds, and HTTP/2 streams to sixteen per connection. | A real silent TCP peer is dropped at the TLS deadline. Management is still tunnel-only; these limits do not eliminate authenticated resource exhaustion. |
| F05 | Three high and four moderate dependency advisories | Tauri resolved Jackson core/databind 2.15.3 on Android. The secure-storage plugin now brings the aligned 2.18.10 BOM into both plugin and application runtime graphs. | Resolved Gradle tree, OSV re-scan, APK build, real native JSON commands, six instrumented tests. Application-specific exploitation was not demonstrated. |
| F06 | Low, privacy hardening | The Android app inherited automatic backup defaults. `allowBackup` and legacy backup are now disabled, and cloud/device transfer exclude all storage domains. Secret storage was already in `noBackupFilesDir`. | Built-APK manifest/resource inspection. Explicit encrypted document export/import remains available. |
| F07 | Medium, UI state safety | Late server-status replies could restore stale metrics or caller-role presentation after disconnect/server changes. Status now belongs to one request generation and one active server; late/unmounted results are discarded. | Three frontend regression tests. Native authorization remains authoritative. |
| F08 | Low, recovery/UI safety | Unknown key-rotation state could unlock sensitive actions, and profile-local state could survive selection changes. Unknown rotation state now locks affected actions; workspace state is keyed by profile identity. | Strict type/build checks, existing rotation/removal tests, state-path review. |
| F09 | Accessibility / navigation | State-opened dialogs lost the initiating keyboard focus. Shared dialog content now restores focus, and page-only browser history supports Android Back. Mobile Linux Settings retains manual updates; Android Home exposes connection failures. The native Android window now uses light system-bar icons over the dark interface in either system theme, and bottom navigation remains fixed in landscape. | Browser focus/Back/action tests, automated WCAG checks, actual Android Back, keyboard, rotation, and system-bar inspection; a regression check requires mobile navigation to stay inside the viewport. |
| F10 | Medium, test reliability | Standalone `! command` assertions could bypass shell `errexit`, allowing a cleanup failure to pass. Failed status proofs and leftover resources now return failure explicitly; remote assertion sequences also stop on failed absence checks. Invalid lint annotations and quoting were corrected. | Two shell regression tests with twenty subcases and zero remaining ShellCheck diagnostics. Indirect trap callbacks have narrowly scoped documented lint annotations. |

The Jackson fixes cover
[async number limits](https://github.com/FasterXML/jackson-core/security/advisories/GHSA-72hv-8253-57qq),
[chunked async parsing](https://github.com/FasterXML/jackson-core/security/advisories/GHSA-r7wm-3cxj-wff9),
[record ignore rules](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-3pjw-73gf-8qr5),
[case-insensitive ignore rules](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-5jmj-h7xm-6q6v),
[address deserialization](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-hgj6-7826-r7m5),
[generic type validation](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-j3rv-43j4-c7qm),
and [array subtype validation](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-rmj7-2vxq-3g9f).
Android documents both the backup default and the manufacturer-specific transfer
exception to `allowBackup=false`; the additional extraction rules cover that
configuration boundary. [Android backup documentation](https://developer.android.com/identity/data/autobackup).

## Maintainability and feature preservation

First-party source changed from **101 files / 66,519 lines / 18 files over 1,000
lines** to **271 files / 73,531 lines / zero files over 1,000
lines**. The exact final inventory is retained in the evidence. Readable
formatting, the redesigned screens, and new checks account for the increased
total line count. The maximum source file is now 998 lines. Thirty-four cohesive
files still exceed the preferred 500-line target; their responsibilities and
follow-up guidance are documented in the [module map](module-map.md).

| --- | ---: | ---: |

| Tauri `lib.rs` | 3,463 | 283 |
| Installer `lib.rs` | 4,666 | 653 |
| Server `lib.rs` | 4,664 | 256 |
| Linux helper `lib.rs` | 4,268 | 488 |
| CLI `main.rs` | 2,260 | 148 |
| Android profile store | 2,258 | 688 |

The connection-screen composition is 108 lines, backed by focused components and
a shared controller. Android compiles its own command modules rather than unused
Linux adapters. The old stylesheet is now an explicit import list with component
and theme sheets. Oversized native tests were separated by behavior. The local
gate enforces the size ceiling and unused frontend locals.

The two Tauri command registries are unchanged: **18 Android and 38 desktop
commands**, including their shared platform command. All **55 distinct UI API
operations** remain present. All **259 existing Rust test functions** were
retained, with six added; all **42 existing frontend tests** were retained, with
three added. Existing persistent schemas and native authorization remain intact.
See the [feature map](overhaul-feature-map.md) for the new location of each flow.

The visual system follows the supplied concepts through dark surfaces, cyan and
violet accents, local branding/illustrations, sidebar and bottom navigation,
power controls, server cards, device administration, and maintenance panels.
Current server/device measurements are used; unsupported concept features and
invented activity history are absent.

the local gate were repeated sequentially. Direct APK assembly through Gradle
also requires Tauri's active build connection; the successful build uses the
Tauri CLI. These were build-orchestration failures, not accepted failing tests.

## Next steps, in priority order

1. **Finish the live network qualification matrix in disposable environments.**
   Exercise established-session fallback, packet loss/MTU/carrier changes,
   DNS failure/interception, unexpected outbound traffic, and both routed IPv6
   and IPv4-only behavior. Re-run the updated fault scripts against disposable
   client/server machines. The existing VPS must remain outside those tests.
   Include real Android consent/enrollment, document-provider backup recovery,
   migration, and disconnect/persistence cleanup; the local and instrumented
   checks do not establish those complete network-backed workflows.
2. **Qualify production releases.** Build/sign an ARM64 Android release, test on
   a physical device, verify reboot/unlock/Always-on/lockdown behavior, and repeat
   manual accessibility checks. Use two independently versioned full Linux
   packages for the power-cut/reboot update gate. Exercise the release-root and
   HTTPS publication gates with appropriate offline signing custody before
   distribution; production signing keys were not accessed in this audit.
3. **Resolve or explicitly accept the upstream Linux dependency risk before a
   public security claim.** Track Tauri's maintained GTK/runtime migration and
   glib unsoundness exposure. Refresh all dependency scans and include bundled
   native libraries/OS packages in the release SBOM review.
4. **Continue incremental simplification.** Split the remaining large cohesive
   state machines only when a behavior boundary and regression evidence justify
   it; consolidate theme overrides as components stabilize. Keep the size,
   compiler, privacy, shell, and UI checks in CI.

General Android membership management, QR-camera scanning, selected-route policy,
persistent wrapped transports, and established-session Android failover remain
pre-existing roadmap gaps. They were not removed by this work and should be
planned as separate features with their own trust and recovery design.
