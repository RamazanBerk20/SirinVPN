# SirinVPN refinement audit — 5 September 2026

This pass keeps the operational design and addresses the latest interface audit, including a custom desktop title bar. It supersedes the connection-preference lifetime and window-decoration descriptions in the [previous report](operational-ux-2026-09-05.md). Existing work remains in the working tree.

| Area | Result |
| --- | --- |
| Window integration | A navy 38px title bar and thin 1px blue-gray outer border replace desktop decorations. The frame stays visible during scrolling and does not intercept clicks or resizing. Minimize, maximize/restore, double-click, dragging, resize edges, keyboard controls, and native close-to-tray handling are connected to Tauri. Launcher/tray activation also restores minimized windows on KDE Wayland. Open dialogs survive these actions. |
| Device measurements | Rates use two compatible readings from the same tunnel. Missing, unsupported, sampling, disconnected, and failed readings have distinct explanations. Failed native byte reads cannot produce a false measured zero. An older helper gets **Review update** with local installation requirements. Duration still comes from the tunnel runtime. |
| Home | The connection block is shorter; device traffic and the complete VPS summary fit the tested 1220×780 viewport. Resource tracks have equal widths. Management response is visible with its actual scope. An unknown activity count shows authorized devices and an unavailable explanation. |
| Connection preferences | Explicit **Save preferences** and **Discard** controls store transport, network conditions, protection, routing ranges, and LAN bypass per server on this device. Saved changes do not modify the running tunnel. Known differences from runtime appear beside the editor. Android stores its supported transport/protection choices per profile. |
| Maintenance | Backup, restore, repair, update, and DNS operations open a readable preparation review while connected. A clearly scoped local disconnect unlocks the existing SSH workflow; execution and identity checks remain enforced. Update/repair descriptions disclose their shared software/configuration operation. Diagnostics has one entry. |
| Navigation and controls | Desktop navigation subtitles are removed. Network conditions use a 2×2 grid. Sticky settings navigation keeps focused controls visible. Member and role labels are explicit, Owner recovery actions are accessible, empty invitations are concise, primary actions stand out selectively, and native selects use consistent navy styling. Android’s compact header respects the actual status-bar/cutout inset. |
| Port forwarding | Empty placeholders produce an instruction to enter both ports. A valid preview uses the same target and numeric values as the submitted rule. Incomplete mappings cannot be submitted. |
| Security corrections | Removing a local server now fails closed if tunnel status cannot be verified. Preference files are private, bounded, versioned, validated, and atomically replaced; invalid files and failed saves preserve the previous configuration. No credentials or activity history are added. |

Window integration follows Tauri's [window customization guidance](https://v2.tauri.app/learn/window-customization/) and [window APIs](https://v2.tauri.app/reference/javascript/api/namespacewindow/). Window-control permissions apply only to desktop platforms. Closing invokes the native close request; it does not destroy the window directly or disconnect the VPN. Notification delivery retains its existing app-owned permission/privacy boundary.

The Wayland test reads only its own temporary window from KWin. This matters because the Wayland client does not receive minimized-state feedback. The temporary KWin script and private test D-Bus session are removed afterward. Native pointer dragging/resizing and keyboard restoration were also exercised through XWayland.

**Verification:** 281 Rust tests, 67 frontend tests, two Python tests, Clippy with warnings denied, formatting, production build, privacy checks, and policy XML validation pass. The optional ShellCheck run was skipped because it is not installed. The source inventory contains **326 files / 81,481 lines, with zero files over 1,000 lines**. File length is a maintainability check, not a measure of architectural quality.

Browser verification covers 11 platform/viewport scenarios, 14 operational fault/enlargement checks, and nine targeted refinement checks. Automated accessibility findings: **zero**. Seven KDE Wayland window/storage checks and seven native WebKitGTK/pointer checks pass. The Pixel 10 emulator passes all six instrumented native tests, three app-preference/notification checks, and native connection-preference persistence through both a WebView reload and a full process restart. Unsupported Android settings are rejected; saving a protection preference does not activate the VPN. Browser metrics and server actions use synthetic responses; these are not live VPN qualification results.

The [evidence manifest](audit/2026-09-05/refinement-audit.json) records final Android verification, artifact paths and hashes, exact source fingerprints, and the remaining boundaries. Review captures include [Home at the default viewport](audit/2026-09-05/refinement-home.png), [Android settings](audit/2026-09-05/refinement-android-settings.png), and [the actual Wayland title bar](audit/2026-09-05/refinement-wayland.png).

**Completion remains 23/24 = 95.8% of the original overhaul acceptance checklist.** This is not a percentage of all possible product features or a security guarantee. The unfinished item is the complete live transport/privacy fault matrix on disposable infrastructure. Invitation expiration, membership lifetime, access roles, and existing VPN protection semantics were preserved.
