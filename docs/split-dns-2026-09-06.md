# Split DNS and resolver diagnosis

Setup and repair support up to 16 explicit domain suffixes, with the most specific
suffix taking precedence. The default policy remains Recursive, DNS over TLS or
DNS over HTTPS. Each split zone selects private IPv4/ULA resolvers over TCP port 53
or authenticated TLS resolvers on port 853. Plaintext forwarding is allowed only
to explicitly configured private addresses. No client uses its ISP DNS for these
zones. Exact private records take precedence over forwarding.

Enter `office.home=10.20.0.53,10.20.0.54` for an unsigned private namespace or
`corp.example=192.0.2.53#dns.example.com` for a DNSSEC-validated TLS zone. Each TLS
zone accepts up to two resolvers; a private zone accepts up to four. The advanced
protocol supports an explicit per-zone exception for unsigned answers, including
private TLS namespaces. Repair's **Keep current** preserves the complete policy;
choosing a replacement DNS policy replaces its split zones too. The CLI accepts
repeated `--split-dns-zone` values during setup/repair.

The generated Unbound policy fixes `forward-first: no` on every zone. Private
names remain scoped to their configured resolvers if all of them fail. The
implementation follows [Unbound's forwarding and local-zone configuration](https://unbound.docs.nlnetlabs.nl/en/latest/manpages/unbound.conf.html).
There is no DNS query history, reporting service or implicit fallback provider.

Explicit diagnostics now send bounded DNS wire requests through the private
resolver and directly to configured upstreams. They report current response time,
connection failure, timeout, TLS authentication failure, refused responses and
SERVFAIL with relevant next steps. These probes run only when diagnostics are
requested; live status sampling does not continuously generate DNS queries. They
query the root NS record and configured split-zone NS records, not browsing data.

Server configuration schema 6 prevents an older binary from silently discarding
split DNS. Setup, repair, server backups and restore preserve this policy. The DoH
proxy and its outbound address restrictions still derive from the explicit default
HTTPS resolvers when split DNS is enabled.

`sh tests/network/run-split-dns.sh` passed with a real Unbound process and synthetic
TCP/TLS resolvers inside an isolated container. It checks authenticated default
TLS, private forwarding, longest-suffix selection, local overrides, and SERVFAIL
without leakage to another resolver. Protocol checks reject invalid/global zones,
public plaintext destinations, mixed secure/plain fallback and duplicates. A real
local TCP exchange checks diagnostic response binding and malformed replies.

The isolated image currently uses Unbound 1.17.1. Full release acceptance on the
target Debian 13 resolver, platform leak checks and real configured upstreams is
still required after implementation.
