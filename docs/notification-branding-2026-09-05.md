# Linux notification branding — 5 September 2026

Linux notifications now identify their sender as **SirinVPN** and display the existing S logo. The installed Tauri notification plugin used the executable basename for both the sender name and automatic icon lookup. Setting the message title alone did not fix either field, which explains the `sirinvpn-desktop` caption and generic document icon.

Both test notifications and connection alerts use the shared app notification module. On Linux it sets the sender and desktop-entry metadata explicitly, supplies an encoded local icon URI, and waits for the notification service to acknowledge delivery. The logo is atomically cached from the bundled PNG, so development builds and AppImages work without an installed icon theme or a persistent AppImage mount. Notification preferences and privacy filtering remain enforced. Other platforms retain the existing Tauri delivery path. The popup frame and typography continue to follow the desktop's notification theme.

Verification passed: 19 desktop Rust tests, desktop Clippy with warnings denied, and the native notification integration test. That test uses an isolated app and D-Bus connection, forwards a test notification to the real Plasma service, checks the sender, desktop entry, exact bundled logo, Unicode/space-containing icon path, disabled-preference rejection, and reported service failure. The actual Plasma popup was visually checked: **SirinVPN** and the S logo appeared correctly. No existing app preferences, active VPN, or VPS were changed. The full-desktop inspection capture was deleted after review.

The current Linux binary and packages are rebuilt. The already-running process retains its old code until **Quit app** and reopening; simply closing to tray does not reload it. The [notification evidence manifest](audit/2026-09-05/notification-branding.json) records the targeted validation and replacement artifact hashes. The earlier policy audit remains a historical record of that pass.
