# UI review 2026-11-01

This review covers screenshots of every UI state in the SirinVPN app, captured by `tests/ui/catalog/full_capture.py` with fictional fixture data in the desktop Tauri window and the Android phone layout, in dark and light themes.

**What was captured.** 657 scenarios: the 549 of the original catalog plus 108 in `coverage_states.py`. On the desktop window (1280×860) and the Android phone layout (412×915), in dark and light themes, that is 2,268 states (165 scenarios exist only on the desktop). Each state has a screenshot of every scroll position, an audit (`audit.js`) and its visible text; the first state of each family also gets a Tab focus pass.

| | Original UI (`main`) | This change |
|---|---|---|
| States captured | 2,268 of 2,268 | 2,268 of 2,268 |
| Screenshots (WebP) | 6,412 (254 MB) | 6,280 (256 MB) |
| English UI messages shown by some state | 1,341 of 1,823 | 1,420 of 1,836 |
| Low-contrast text (state hits / distinct elements) | 114 / 24 | 0 / 0 |
| Text under 12px | 3,684 / 105 | 16 / 1 (fixed after the capture: one 8px font shorthand) |
| Touch targets under 24px (desktop) or 44px (Android) | 1,160 / 59 | 352 / 15 |
| Tab stops without a visible focus ring | 14 / 4 | 14 / 4 (dialog headings) |

The tooling this replaces captured only the desktop window in the dark theme: 549 states that showed 1,116 of the 1,819 messages. Both columns above were captured with the same harness: the original UI was served from `main` with `tests/ui/catalog/serve_ui.sh`.

**Structure.** The stylesheets were 6,608 lines in 35 files that overrode each other: the sidebar alone was styled in 10 files. The app shell now has one home (`styles/shell.css`), 262 declarations that a later rule with the same selector always overrode were removed (a before/after capture of 967 states was pixel-identical), and `tests/unit/test_css_overrides.py` keeps both from coming back. The stylesheets are now 6,191 lines in 34 files.

Nine reviewers each took a group of state families and judged every state sheet, together with the full-size originals and the audit output. Their findings are merged and deduplicated here and ranked P1 (blocks or seriously misleads a task, or visibly broken layout), P2 (clearly hurts usability) or P3 (polish). Within each severity, findings are ordered by how many users and states they affect, and the tag says where each was seen: desktop, android or both.

## Findings

### P1

- **UX-01** [both] Errors don't name the failed action and rarely offer a retry. Nearly every failure shows only backend text with no Try again (`home/connect-operation-failed`, `devices/device-list-failed`, `wifi/refresh-network-failed`, `hetzner/hetzner-plans-failed`), because `errorMessage()` in `apps/desktop/src/lib/errors.ts` drops the action message; the stock "VPS operation could not complete" wording is the fixture's. **Fix:** lead with the action ("Couldn't load devices"), add the backend detail as a second line plus Try again, and never blame the VPS for local actions.
- **UX-02** [both] Validation errors look like helper text, or bad input is accepted silently. Invalid values get a grey hint, a faint border or nothing while Save stays enabled, in MTU (`measurements/invalid-manual-mtu-1421` even says "Saved"), member policy, invitation uses, local networks, blocklists, routes (`routing/empty-selected-routes`), ports (`provisioning/invalid-transport-port`), split DNS, release URLs and repeat passwords. **Fix:** validate on input, show a red message with an icon under the field naming the bad value, set `aria-invalid`, and block Save until valid.
- **UX-03** [both] Results and errors appear far from the control that caused them, often off-screen. The VPS update result renders below the fold (`vps-updates/install-reviewed-vps-update-completed`), Android recovery-key copy and save feedback lands a screen below (`recovery-keys/recovery-key-copy-failed`), repair errors hide behind the sticky footer, and cancel-invitation, member-action, test-notification and alert-test feedback shows at the top or bottom of the page. **Fix:** show feedback next to the triggering control (or as a toast) and scroll it into view.
- **UX-04** [both] Home stays green while protection is broken or unknown. With IPv6 not routed, the kill switch failed or its state unknown, Home keeps "Connected" and "All internet traffic goes through the VPN." (`home/ipv6-protection-unavailable`, `protection/kill-switch-failed`, `home/protection-state-unavailable-home`), Android shows "VPN monitor not responding" in green, and the alerts offer no fix. **Fix:** amber headline and ring, an honest subline ("IPv6 traffic may bypass the VPN"), and an action (Reconnect, Retry check, Open VPN settings).
- **UX-05** [both] Interrupted connections keep "Disconnect" as the main action and hide that traffic is unprotected. `home/connection-interrupted-home` uses neutral connecting copy and never warns that traffic leaks with the kill switch off, and `protection/recovery-waiting-for-user` keeps the ring as "Disconnect" (which lifts the block) with a small Reconnect and a dead Connect in the Server card. **Fix:** amber state, a subline saying traffic is unprotected or blocked, "Reconnect" as the hero action, "Disconnect and unblock" secondary.
- **UX-06** [both] Irreversible actions run without stating consequences or confirming. "Remove from this device" deletes the key on one tap (`removal/remove-local-server-in-progress`), the final "Uninstall SirinVPN" never says every device loses access, the replace-installation warning is 10px grey (`provisioning/replace-existing-installation-warning`), owner recovery's revoke consent is a plain checkbox, "Clear" private DNS records looks like "Keep current", and Hetzner's "Delete this server" is a neutral first button. **Fix:** a confirm step that names the consequences, with a danger-styled final button.
- **UX-07** [desktop] "Server key changed" warnings look routine. In repair, updates, backup and restore (`vps-repair/vps-repair-ssh-fingerprint-changed`, `vps-updates/vps-updates-ssh-fingerprint-changed`, `vps-backup/vps-backup-ssh-fingerprint-changed`) the possible-interception warning uses the neutral key icon and puts "stop and contact your provider" in the smallest text (10–11px), and first-time verification's "If it doesn't match, don't continue" is 10px too. **Fix:** a danger banner at the top with body-size advice, Cancel as default, and a decision-named primary ("Replace saved key").
- **UX-08** [both] The kill switch toggle shows ON but only applies from the next connection. The only notice is at the bottom of the page, below the fold (`connection/kill-switch-saved`, `connection/all-protection-preferences-saved`), so users believe they are protected now. **Fix:** an inline note under the kill switch row when saved and live values differ ("On from your next connection. You're not protected yet.") with a "Reconnect now" button.
- **UX-09** [both] Server-side faults render as a healthy connection. `home/server-interface-down`, `home/no-recent-handshake-home`, `home/device-rotation-pending` and `home/local-component-update-required` are identical to `connected-home` ("Server reachable: Responding", "Live"); confirm first that the fixture field names match what Home reads. **Fix:** if they match, show an amber headline and banner ("Server's VPN interface is down", "No handshake for N min") and Home banners linking to rotation and component updates.
- **UX-10** [both] "Another server is connected" is a dead end. `home/other-server-active` says "Disconnected" and "Open it to disconnect", but nothing opens it ("See active server" is plain text, Connect is disabled), and `connection/startup-other-server-active` doesn't even name the other server. **Fix:** headline "Connected to <other server>", a primary "Switch to this server" button, and a real link to the other server.
- **UX-11** [android] The Connection page contradicts itself and reports desktop-only settings. Automatic reconnect says "applies immediately" while the footer and banner say "next connection" (`connection/automatic-reconnect-saved`), and banners, Current status and System health list "Kill switch: off" and "Connect on startup: off", which Android doesn't have (`connection/all-protection-preferences-saved`, `settings/maintenance-settings`). **Fix:** build Android banners and status rows only from Android settings ("Block connections without VPN"), and keep immediate settings out of the next-connection banner.
- **UX-12** [both] The routing save bar appears without edits and covers content. `routing/saved-routing-full-tunnel` loads with "Unsaved changes" beside "Saved for your next connection" because `useConnectionPreferences.ts` empties `included_routes` outside `selected_routes` mode, and the ~200px Android card covers "Allow local network" (desktop covers the blocking card). **Fix:** compare `included_routes` only in `selected_routes` mode, dock the Android bar as one row above the bottom nav, and pad the scroll area by the bar height.
- **UX-13** [desktop] Startup screens have no title bar or window controls. On `startup/error-clientplatform` and `startup/loading-clientplatform` the frameless window has no drag region or close button, because `<DesktopTitleBar/>` renders only after the platform is detected, so a hung detection leaves a window that can't be moved or closed. **Fix:** render the title bar whenever the app runs under Tauri, before the platform resolves.
- **UX-14** [both] A failed preferences load shows defaults as if they were saved. `connection/preferences-error` keeps the form with default values under "Saved for My private VPS on this device" and a stuck "Loading…", so users think their kill switch was reset. **Fix:** replace the form with a load-error state ("Couldn't load connection preferences" with Try again) and never present defaults as saved values.
- **UX-15** [desktop] The sidebar server list clips and hides entries. With more than about four servers (`servers/12-saved-servers`, `extremes/twelve-servers-home`, `servers/long-server-names`), the active card is squashed so "Connected" spills under its border, and the fifth entry is cut off by the footer with no scroll cue. **Fix:** `flex-shrink: 0` and a min-height on items, and make the list a scroll container with a visible fade or scrollbar.
- **UX-16** [desktop] Device and member menus overflow the window. The "⋯" menu (`devices/menu-morgans-laptop`) prints a "Device"/"Member" caption on every item, interleaves the categories, and fits only 6 of 12 actions, hiding Revoke, Transfer ownership and Port forwarding with no scroll cue. **Fix:** Android's grouped headings (Device / Member / Ownership) with destructive items last, a height cap with a scroll cue, or flip the menu upward.
- **UX-17** [desktop] The app-routing Program field doesn't look like a field. On `routing/application-routing-linux-namespace` and the other app-routing states, "Program" is an unstyled 15px-high line with the path in tiny grey text above "Browse…". **Fix:** standard bordered input styling (40–44px) with "Browse…" inline to its right.
- **UX-18** [desktop] Updates can't start without a release URL users don't know. `vps-updates/update-setup-choose-source`, `app-updates/desktop-app-update-dialog` and `onboarding/first-launch-app-updates` show an empty "Release source" with no default or example, and the app dialog forgets it after each check. **Fix:** prefill the source the server was installed from (or the official one), remember it, add a placeholder and a "Where do I find this?" link, and append the trailing `/` automatically.
- **UX-19** [desktop] Update dialogs offer actions their own warnings rule out. `app-updates/installer-kind-unsupported` and `release-already-current` say the release can't be installed yet show the confirm checkbox, Install and "Open connection settings", and `vps-updates/installed-receipt-mismatch` says "Repair the server before updating" with no Repair button while "Check for updates" stays enabled. **Fix:** hide install controls when installing isn't possible, put "Repair VPS…" in the mismatch banner, and disable checking until repaired.
- **UX-20** [both] The new recovery key appears inside Admin recovery with no heading or real warning. On `recovery-keys/create-offline-recovery-key-completed` the one-time key sits under the collapsed Admin recovery row, and "Store this key offline… can't be shown again" is muted body text. **Fix:** place the panel under Owner recovery with a heading ("Your new recovery key") and a warning callout, and hide Replace/Revoke and Admin recovery until Finish setup.
- **UX-21** [both] Recovery-key issuance is a dead end when unavailable. `recovery-keys/recovery-issuance-unavailable` shows only "No recovery key yet." with no button and no reason. **Fix:** say why this device can't issue a key and what unlocks it ("Only an Owner device can create the recovery key", "Update the VPS first"), with a button to that action.
- **UX-22** [desktop] A failed install sends the user back to the first form step. After `provisioning/install-new-vps-failed` (+ `password-install-failed`) the view looks like a fresh form with the error below the fold, the fingerprint and network checks must be repeated, and nothing says whether the server was changed. **Fix:** stay on the install step with a failure panel (phase, whether the server changed, "Retry install" / "Back to settings") and keep the verified fingerprint.
- **UX-23** [desktop] Wi-Fi auto-connect says "off" right after it is turned on. On `wifi/enable-wifi-automation-completed` the toggle is on but the status reads "Auto-connect is off.", because WifiSettings shows the stale `disabled` status. **Fix:** show "Starting…" until a new status arrives, and never show `disabled` while the toggle is on.
- **UX-24** [android] The invitation copy-failure advice is impossible to follow. `invitations/invitation-copy-failed` says "Select it and copy it manually", but Android never shows the code, and the code is shown only once. **Fix:** "Couldn't copy the code. Tap View or share invitation to share it instead.", or open the share screen directly.
- **UX-25** [android] A long fingerprint widens the Hetzner page and cuts off its buttons. On `hetzner/hetzner-kept` the unbreakable "SHA256:…" inside a sentence pushes the error box, token helper, "Delete this server" and "Wait again" past the right edge (real base64 fingerprints don't break either). **Fix:** put the fingerprint in the wrapping monospace box join already uses (or `overflow-wrap: anywhere`), and add `min-width: 0` to the mobile page container.

### P2

- **UX-26** [both] Disabled primary buttons look half-enabled and never say why. The gradient stays at reduced opacity (white on pastel in light theme, about 2.3:1), and nothing says what's missing on "Create backup", "Verify server", "Restore backup", "Review invitation", "Save alerts", "Launch in VPN" or "Test notification" (`onboarding/add-server-backup`, `key-rotation/rotate-desktop-device-keys-failed`); Members see owner-only "Invite member" disabled (`devices/member-device-list`). **Fix:** a flat neutral disabled style, a one-line reason next to the button, and hide actions the role can never use.
- **UX-27** [both] Busy states don't show what is running. Long operations show text without spinner or step while sections grey out or stay editable and the close X and first-launch tabs stay active (`vps-updates/install-reviewed-vps-update-in-progress`, `wifi/refresh-network-in-progress`), and labels are generic ("Working…") or land on the wrong button (recovery keys' shared `busy` flag). **Fix:** a spinner and verb on the pressed button ("Refreshing…", "Getting prices from Hetzner…"), with the rest of the form locked.
- **UX-28** [both] The busy footer contradicts the body. "Working… You can close this when it finishes." appears under "Keep the app open until this finishes." in backup, restore, uninstall, key rotation, invitations and member policy (`vps-backup/vps-backup-operation-in-progress`, `key-rotation/rotate-desktop-device-keys-in-progress`, `member-policy/save-member-policy-in-progress`), repeating the busy label, and Android has no close button. **Fix:** remove the footer and keep one accurate line next to the spinner.
- **UX-29** [both] Successful actions give no confirmation. Imports, removals, renames, revokes, saves and member actions just change a list or land on Home (`device-backups/device-import-completed`, `member-actions/enable-mutual-device-access-confirmation`, `owner-recovery/recover-owner-access-completed`, `recovery-keys/revoke-registered-recovery-key`), and endpoint shows success as a disabled button ("Published on old VPS") and "no update waiting" as a red error. **Fix:** a short toast or status line naming the result ("Pair removed", "Networks saved"), using success and info styles.
- **UX-30** [both] On/off switches are hard to tell apart in the light theme. ON is a pale teal track (1.86:1 against the card) and OFF a pale grey track, both with the same navy knob, so knob position is the only cue (`connection/*`, `general/close-to-tray-enabled`, `wifi/enable-wifi-automation-completed`, `android/connection-subpage`). **Fix:** in the light theme use a saturated accent track with a white knob for ON, as the dark theme does.
- **UX-31** [both] Tap targets are small and segmented controls don't fit their row. On Android, disclosure summaries are 18–24px tall and the Sign-in method, endpoint tab, theme and copy buttons are 40px (`vps-backup/vps-backup-ssh-details`, `recovery-keys/recovery-qr-expanded`), while two-option segments fill half the track and three-option ones leave an orphan cell (or an empty fourth column on desktop, `dns/desktop-private-dns-records`). **Fix:** 48dp minimum, segments `flex: 1`, and a grid sized to the option count.
- **UX-32** [both] Important warnings and captions are set at 7–11px. Examples are "A lost password can't be recovered." and "This file can impersonate this device…" (`dialogs/export-device-backup`), the invitation warning and expiry, "Keep SirinVPN open" during Hetzner creation and install, "0 OF 32 USED", port-forward rule text and the endpoint old→new row (`endpoint/share-migration-introduction`). **Fix:** captions at least 12px (12sp), warnings and code chips at body size, and no uppercase micro-labels for counts.
- **UX-33** [both] Some failures are plain grey text that reads like a description. `measurements/mtu-apply-failed`, `general/preferences-save-failed`, `routing/launch-application-failed`, `dns-blocking/blocking-failure-download` and `vps-alerts/alerts-delivery-failing` look like ordinary notes, while other pages use the red `InlineError` box. **Fix:** route every failure through `InlineError` (or a shared warning variant for "last good list stays in effect") next to its control, with a retry where it makes sense and a hint for HTTP 4xx alert errors.
- **UX-34** [both] Collapsible sections use several styles, and some look like text fields. "Admin recovery" and "Permissions and schedule" are marker-less bordered boxes, and Admin recovery's body has no padding (`settings/recovery-settings--expanded`, `invitations/new-member-invitation`), while elsewhere native ▶, "–" and chevrons mix, nested summaries outsize their parent, and rows are 21–23px tall. **Fix:** one shared disclosure component with a chevron, card padding and at least 32px height (48dp on Android).
- **UX-35** [both] "Update the server" notices give no way to update. Older-VPS limits are bare text: `connection/unsupported-manual-transports` (repeated on four disabled cards at 2.78:1), `measurements/mtu-component-unsupported` (toggle stays on), `devices/older-vps-device-capabilities`, `recovery-keys/recovery-unsupported-vps`, `dns-blocking/blocking-unsupported-vps`, `port-forwarding/unsupported-vps`, `vps-alerts/alerts-unsupported-vps`, `routing/windows-driver-unavailable`, `device-backups/unsupported-backup-version`. **Fix:** one readable notice per page with an "Update VPS", "Repair VPS" or "Check for updates" button.
- **UX-36** [both] "Connect first" and similar instructions come without a button. `settings/network-settings-disconnected` (three phrasings), `endpoint/share-migration-disconnected`, `devices/disconnected-device-list` ("Open Home" adds a step), `wifi/automation-needs-attention`, `vps-repair/vps-repair-operation-completed`, `android/details-subpage-disconnected`, "Turn on the kill switch in Connection settings" and `device-backups/duplicate-backup-identity` all leave the user to find the place. **Fix:** one message per page with a button that does it in place ("Connect", "Open Connection settings", "Open existing server").
- **UX-37** [both] Loading states show default values with an off-screen "Loading…". `connection/preferences-loading` and `general/app-preferences-loading` show defaults (Theme "System") half-disabled with "Loading…" below the last card, `recovery-keys/recovery-failed` keeps "Loading…" under its error, and the invitation capability check replaces the form so the dialog jumps. **Fix:** a skeleton or "Loading preferences…" at the top, no selected values until data arrives, and the error replacing the loading text.
- **UX-38** [both] Save-state messages in Settings overlap and some are wrong. Up to three "next connection" messages show at once with doubled colons, the page footer "Changes apply on your next connection." also covers DNS, blocking and port forwarding, which apply at once (`connection/connection-preferences-saved`, `settings/network-settings`), and DNS blocking says "off" after ticking with no unsaved marker (`dns-blocking/blocking-enabled-unsaved`). **Fix:** one status line only when saved and live values differ, notes scoped to their card, and an unsaved marker.
- **UX-39** [both] Back controls are tiny or duplicated. "Back" is a bold centred line with a 17px-high hit area above the content (`vps-repair/vps-repair-ssh-fingerprint-changed`, `provisioning/probe-new-vps-completed`, `removal/uninstall-fingerprint-review`), and on Android it sits under the app bar's back arrow, while the troubleshooter's header ← closes and its footer Back goes to the previous step. **Fix:** a left-aligned "← Back" at least 36px tall on desktop; on Android let the app bar handle back and name the footer "Previous step".
- **UX-40** [both] Keys, hashes and fingerprints are truncated, unlabelled or can't be copied. Root and signing keys are cut with "…" and lack Copy (`app-updates/desktop-verify-app-release-completed--expanded`), the backup checksum is a bare unlabelled box (`vps-backup/vps-backup-operation-completed`), the key-rotation fingerprint chip is unlabelled 9px text, and the server fingerprint appears four different ways across provisioning, join, owner recovery and Hetzner. **Fix:** one labelled hash component showing the full, wrapping value with Copy.
- **UX-41** [android] "Enter securely" fields look like buttons and never confirm entry. They read as disabled inputs in dark and buttons in light, match the "Choose file" button, and never show "Password entered" or "Passwords match" (`dialogs/export-device-backup`, `vps-updates/vps-updates-sudo-login`, `vps-backup/vps-backup-ssh-details`). **Fix:** style them as inputs with a lock icon and a specific label ("Enter SSH password"), then show "Password entered · Change" and a match tick.
- **UX-42** [both] The Devices list never shows whose device is whose. "Members and devices" is a flat list with only an IP and role (`extremes/many-members-and-devices`), so a member action from one device silently changes another (`member-actions/suspend-member-confirmation`), "Suspended" looks like idle (`devices/member-suspended`), and device-less member cards have no chevron. **Fix:** group devices under member headers (or show the owner name), add a distinct Suspended badge, and give member cards a chevron.
- **UX-43** [both] Technical screens use internal jargon. Release review ("sequence 2", "x86_64-unknown-linux-gnu"), Diagnostics ("Local listeners cannot establish public reachability", "Reported by service") and startup status ("Startup connection saved, not active.") are hard to read, and Diagnostics lists "Not checked" items under To review and again under Passed (`app-updates/desktop-verify-app-release-completed`, `diagnostics/diagnostic-report-failures`, `connection/startup-saved-not-active`). **Fix:** plain wording ("Linux (64-bit)", "Will connect to My private VPS when this device starts") and a separate neutral "Not checked" group.
- **UX-44** [both] The power ring doesn't follow the connection state. On desktop it is the same gradient in every state, on Android `home/protection-verified-home` labels it "VPN settings" with a power icon, and `home/local-status-loading`, `-stale` and `-unavailable` are identical, label it "Refresh status" and show an error while still loading. **Fix:** state colours (green, neutral, pulsing, amber), "Checking VPN status…" while loading, a refresh icon when stale, and "Disconnect" on Android with a separate settings link.
- **UX-45** [both] Transitional states show conflicting labels and controls. Connect and disconnect both show "Changing connection…" with "Stop VPN" while the text says traffic isn't using the VPN and the sidebar says "Disconnected" (`home/connect-operation-in-progress`), and resume-paused shows ring "Disconnect", a "Reconnect" button and a disabled "Connect" at once (`home/resume-paused-connection-completed`). **Fix:** "Connecting to My private VPS…" / "Disconnecting…" with "Cancel", the sidebar in sync, and one Reconnect action on the ring.
- **UX-46** [desktop] Disconnected Home is full of empty values. `home/disconnected-home` and every not-connected state show three "Not connected" tiles, "Method Not active / Routing Not active", a second (usually disabled) Connect button and Device details full of "Unavailable". **Fix:** one empty-state line, no duplicate Connect, and Method, Routing and Device details hidden until connected.
- **UX-47** [both] Home doesn't warn about degraded quality or resources and contradicts itself on reachability. "Server reachable: No reply" sits beside "Server response 28 ms", packet loss still says "Responding" while Device details show 228 ms and 3 of 8 lost (`home/quality-packet-loss-home`), and CPU 98.7% and storage 97% use healthy cyan with no Android hint (`home/server-high-resource-usage`). **Fix:** one reachability/latency line, an amber "Unstable connection" notice, amber/red bars at 85%/95%, and a Home alert on both platforms.
- **UX-48** [both] The active method and automatic switches are invisible on Home. Android Home always shows "Method: Automatic", desktop labels HTTPS and TLS-like transports both "TLS fallback" (`home/tls-like-connected`, `home/https-transport-connected`), and switch reasons and rollbacks render only in VPS maintenance (`measurements/transport-*`). **Fix:** show "Automatic · TLS fallback" and the last switch reason next to Method, and give HTTPS its own label.
- **UX-49** [desktop] The kill switch status row is confusing. "Kill switch: Blocking traffic" shows while connected and reads as "your internet is blocked", "IPv6 not verified" hangs under the kill switch column, and "Disconnecting also lifts the kill switch block…" shows even when nothing is blocked (`protection/kill-switch-blocking`, `home/protection-verified-home`). **Fix:** "On" while connected, "Blocking traffic" only when disconnected or interrupted, IPv6 as its own item, and the caveat only when it applies.
- **UX-50** [both] Home alerts split the status block, and "Run diagnostics." isn't a link. On `home/dns-service-unhealthy`, `home/ipv6-protection-unavailable` and `home/unverified-application-routing` banners are inserted between the status sentence and the Method/Routing row, shifting it 30px. **Fix:** make "Run diagnostics" a button and give alerts a fixed slot below the status row.
- **UX-51** [both] Two "automatic" controls decide one thing. "Choose method automatically" (on) sits above "Network conditions" with "Auto – Detects what works" also selected, and neither explains the other (`connection/saved-network-normal`, `settings/connection-settings`, `android/connection-subpage`). **Fix:** merge them into one choice, or disable Network conditions while automatic is on and rename it "Network type (helps automatic choice)".
- **UX-52** [both] Manual MTU mode still promises an automatic change. With "Automatic packet size" off, the card says "Pending change 1360 bytes · not applied yet" and "A smaller packet size was measured and will be applied." (`routing/manual-packet-size-1280`, `measurements/invalid-manual-mtu-575`). **Fix:** in manual mode hide Pending change and that sentence, and offer the measured value as a suggestion ("Measured 1360. Use this value").
- **UX-53** [both] The saved-login keyring error uses jargon and has no retry. "The desktop wallet is locked. Unlock it and try again." offers only "Forget saved login" as a centred link (`vps-repair/vps-repair-ssh-wallet-error`, `vps-updates/vps-updates-ssh-wallet-error`, `vps-backup/vps-backup-ssh-wallet-error`), and after a fingerprint failure the primary still says "Continue". **Fix:** "Your system keyring is locked" (platform-specific), Try again as the main action inside the banner, and Forget as a secondary option.
- **UX-54** [desktop] Dialog action buttons scroll out of view. With Verification details open, Discard and Install update are cut off at the bottom (`app-updates/install-appimage-failed--expanded`), and during the SSH check the busy button scrolls away, leaving only "Working…" (`vps-backup/vps-backup-ssh-fingerprint-checking`). **Fix:** a sticky footer outside the scrolling body in ReleaseUpdateDialog and the backup and restore dialogs, as VpsUpdateDialog has.
- **UX-55** [both] Long server names can't be told apart. In the desktop sidebar all four long names truncate to the same "My private internation…" (`servers/long-server-names`), and in the Android picker the favourite star shrinks to a dot and the rows misalign (`android/server-picker-long-names`). **Fix:** two lines with an ellipsis (or middle truncation), a full-name tooltip, and `flex-shrink: 0` on the star.
