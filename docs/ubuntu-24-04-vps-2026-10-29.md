# Ubuntu 24.04 LTS VPS support

The installer now accepts `ID=ubuntu`, `VERSION_ID=24.04` (every 24.04.x point
release) on `x86_64` and `aarch64`, alongside Debian 13. Other releases,
including Ubuntu 22.04 and 24.10, are still rejected before any change. The
install transaction is the same on both distributions; there is no
distribution-specific branch beyond these:

- The package step sets `NEEDRESTART_SUSPEND=1`. Ubuntu server images ship
  needrestart, whose apt hook otherwise restarts services that use upgraded
  libraries in the middle of the install. On Debian the variable has no effect.
- Network preflight detects UFW with `ufw status` instead of
  `systemctl is-active ufw`. Ubuntu's `ufw.service` is a oneshot that stays
  active while UFW itself is disabled, so the old check reported UFW on every
  Ubuntu host. An enabled UFW gets a non-blocking note. SirinVPN does not
  change UFW.

## Verified on 2026-10-29

Everything below ran on a local workstation. No Ubuntu VPS or VM was
provisioned.

- **Repository gate.** `./scripts/test.sh` passed on this change, including the
  Rust workspace tests and 233 desktop tests.
- **Installer unit tests.** The compatibility gate accepts Debian 13 and
  Ubuntu 24.04 on both architectures and rejects other versions and
  architectures. An enabled UFW gives exactly one non-blocking note. The
  systemd-resolved stub listeners on 127.0.0.53 and 127.0.0.54 are not treated
  as conflicts with SirinVPN's DNS listener on 127.0.0.1 and 10.77.0.1. This
  holds whether or not `ss` adds the `%lo` device suffix to the address.
- **Packages and paths, `ubuntu:24.04` container (24.04.5).** All six
  dependency package names install: wireguard-tools 1.0.20210914-1ubuntu4,
  nftables 1.0.9, unbound 1.19.2, dns-root-data, iproute2 6.1.0 and
  ca-certificates. `/usr/share/dns/root.key` and
  `/etc/ssl/certs/ca-certificates.crt` exist. Unbound's packaging matches
  Debian 13: `include-toplevel` over `unbound.conf.d`, the same two default
  drop-ins, the same `unbound-resolvconf.service`, an AppArmor profile, and a
  `/sbin/resolvconf -> resolvectl` link. The absolute tool paths used by the
  server (`/usr/bin/ss`, `/usr/bin/wg`, `/usr/bin/systemctl`, `/usr/bin/timeout`
  and `/usr/sbin/runuser`) exist.
- **Generated configuration.** Install scripts were generated for Recursive,
  DNS-over-TLS, DNS-over-HTTPS with IPv6, and split DNS, each with private A and
  AAAA records. Every file the scripts write was then checked with Ubuntu's
  tools: `sh -n` (dash) for the scripts and helpers, `unbound-checkconf` 1.19.2,
  `nft -c` 1.0.9, and `systemd-analyze verify` (systemd 255) for every
  SirinVPN unit, timer and the unbound drop-in. All passed. A Debian 13
  container (unbound 1.26.2, nftables 1.1.3, systemd 257) ran the same checks
  as a control, and they all passed there too.
- **needrestart.** In 3.6-7ubuntu4.5, `/usr/lib/needrestart/apt-pinvoke` exits
  without running needrestart when `NEEDRESTART_SUSPEND` is non-empty.
- **UFW.** `ufw.service` in 0.36.2 is `Type=oneshot` with
  `RemainAfterExit=yes`. The preflight probe printed nothing while UFW was
  disabled and printed `ufw` after `ufw --force enable` in an isolated
  container network namespace. Enabled UFW set both the `INPUT` and the
  `FORWARD` policy to `DROP`.
- **Payload ABI.** The 2026-10-14 payloads from
  `packaging/Dockerfile.server-payloads` (unchanged since 2026-09-27; Bookworm,
  glibc 2.36) need at most `GLIBC_2.34`, and link only libc, libm and
  libgcc_s. The x86_64 payload ran `sirinvpn-server --help` in Ubuntu 24.04.5
  (glibc 2.39). The aarch64 payload got the same static ELF check but was not
  run.

## Not verified

- **No end-to-end run on Ubuntu.** Nobody has provisioned an Ubuntu 24.04 VPS
  or VM yet. So these are all unverified there: install, verification, the
  five-minute rollback guard, the transports, private DNS, the kill switch,
  repair, restore, uninstall, signed VPS updates, and the
  `sirinvpn-security-update` timer.
- **Ubuntu's kernel.** `nft -c` ran on the host kernel (7.2), not Ubuntu's 6.8
  kernel. WireGuard and nftables behavior on 6.8 was not exercised.
- **aarch64.** The aarch64 payload was not run on any Ubuntu host.
- **Booted-host behavior.** Neither of these was exercised on a booted Ubuntu
  host. Both distributions ship the same packaging for them.
  - **systemd-resolved.** When `/sbin/resolvconf` exists,
    `unbound-resolvconf.service` registers 127.0.0.1 with systemd-resolved.
  - **AppArmor.** The unbound profile is enforced.
- **UFW when enabled.** Preflight reports an enabled UFW; it does not check
  which UFW rules the VPN needs. Expect the listed ports, tunnel DNS and
  management on `sirinvpn0`, and forwarded tunnel traffic to be dropped until
  matching rules are added.
- **dpkg lock after first boot.** On a freshly created cloud VPS,
  unattended-upgrades can hold the dpkg lock. The dependency step then fails
  before any SirinVPN change and has to be retried. This is not mitigated, and
  it applies to Debian cloud images too.
- **Payload rebuild.** The payload was not rebuilt from this commit. The
  change does not touch server code or the payload Dockerfile.
